1. **[wrong receipt] The merged-head envdiff cannot show that a universe lift preserved a statement; "0 in the unexplained bucket" is true by construction.** INTEGRATION-7 §3 says the 1,028 changed types are "all in the tool's unchanged-dependency class (a universe or binder generalisation keeps the `uses` set); 0 in the unexplained bucket". The tool's class is actually called `PROOF-NAMING` (`changed_type_proof_naming`, 1,028 entries; `changed_type_source` empty), and its definition (`/home/goblin/lean-agent-ide/tools/envdiff.py` line 52) is: the name's `uses` set — *restricted to the reported modules* (`Lib.*`) and with `._proof_n` edges dropped — is unchanged. It sees nothing that names only Mathlib/core constants. Shapes it classifies as PROOF-NAMING and passes: (a) an added hypothesis `[MetrizableSpace X]`, `[Finite ι]`, `(h : 0 < n)`; (b) a weakened conclusion `IsIso f` → `Mono f`, `Bijective` → `Injective`, `n` → `n + 1`; (c) the universe shape asked for: in a declaration that is already polymorphic in `u`, a body-level `∃ Y : Type, …` widened to `∃ Y : Type u, …` — literally unchanged at `u = 0`, but every consumer at `u = 1` (which existed before) now gets a different, weaker proposition (`Small`-style predicates become trivial), with the same `uses`. Demonstrated on the tool itself: two two-row tables differing only in `Demo.foo`'s `typeHashPublic` with identical `uses` give `PROOF-NAMING Demo.foo … VERDICT PASS` (files under `review-pass/r7-merged-head/{before,after}.jsonl`). So the merged-head check verifies only "nothing lost, nothing added, no Lib-internal dependency changed"; statement preservation rests entirely on the per-packet receipts, and at least packet 02's receipt says its 233 were "checked mechanically" by the same `uses`-list criterion. Mitigation I did: 120 random names of the 1,028, declaration header at `9552305f` vs `d950428a` compared after stripping `.{…}`, `Type u`/`Type*`/`Sort u` — 115 identical, 4 auto-generated (`_assoc`, structure field) not locatable, 1 benign (binders of `TopCat.Sheaf.equivalenceOfIso_functor_additive` moved to a `variable` line). ## Tool notes

- `envdiff` should (i) rename `PROOF-NAMING` to what it tests (`same-Lib-uses`), (ii) additionally hash each type with all universe parameters instantiated to 0 and report equality of that hash before/after — a pure universe lift then verifies mechanically, and a hypothesis or conclusion change becomes a distinct class regardless of where its constants live, and (iii) include Mathlib constants in `uses` (or a separate `usesExternal`) so a `[MetrizableSpace X]` shows up as a dependency change.
- A coordinator summary should quote a receipt's own headline figures verbatim (or say "derived: sum of column X"); the two invented/derived cells cost the most time to trace.
- Receipts that say "checked mechanically" should say which property was checked; "has a generalised declaration in its `uses` list" is not "statement unchanged".
- The merged-head receipt would be more trustworthy with the dump command lines and the commit each dump was taken at written into the `.txt`, next to the `before`/`after` paths.
- `Solution.lean`'s single `#print axioms` is not an audit of anything the final theorem does not use; moves to `Hopf/Proof` should be accompanied by a `Hopf/Proof/AxiomAudit.lean` probe as a standing rule, not an owner decision.
